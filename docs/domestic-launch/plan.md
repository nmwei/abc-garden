## 背景、目标与非目标

目标按优先级排列：

1. 国内设备能稳定访问正式域名，保住现有本机学习数据。
2. 家长配置和学习存档可恢复：换设备或清除网站数据后，重新登录可找回最后一次成功同步的记录。
3. 保留离线学习体验；网络或账号服务故障不阻断已有本机内容的练习。
4. 新版本以自有服务器为正式发布目标，GitHub 继续用于源码托管。

已确认范围：先在 ABC 打通完整闭环，后续接入阅读与数学；产品目标为公众可自助注册，不采用邀请制。上线前的自家设备验收是发布测试，不改变公开注册目标。

继续允许游客在本机学习；家长在需要云端保存时注册/登录，孩子不必为开始练习单独建立账号。公开注册仅开放账号申请，个人存档仍保持私有。

首期不包括：手动文件导入导出、昵称头像编辑、手机号换绑、退出所有设备、注销账号、自定义照片上传、多人家庭权限管理、复杂自动合并、营销获客体系、收费、排行榜、行为分析平台、录音和作品云盘、服务器实时 TTS、前端框架重写。公开注册与短信重设密码属于首期。微信按已确认的资质限制移出本期。Apple 暂列后续能力。

## 关键设计决策

### D1. 正式域名继续建设，旧站仅补一次迁移入口

旧 GitHub 站在原设备和浏览器读取白名单本机数据，通过打开新网站窗口并校验双方 origin、窗口引用和随机握手标识传递。新网站完成登录和显式接收，再走正常 revision 条件写入；旧站不接触登录 Cookie，不持有账号凭证，不删除原记录。禁止在 URL 中携带学习数据或账号令牌。失败、源窗口关闭或格式不兼容时保留旧记录。

旧站使用独立补丁脚本，仅修改 index、迁移脚本、Service Worker 与预缓存版本；不把新账号网站整包覆盖旧站。`npm run package:legacy -- /new/patch-directory` 基于本地 origin/gh-pages 生成覆盖补丁，发布前需重新 fetch 核对该分支与服务端正式版本。本轮只准备和验证，不推送或发布。

不提供手动文件导入导出。三个花园继续使用 ECS 发布，GitHub 托管源码；旧站迁移是一次性例外。源码推送和服务器发布分别执行。

### D2. 一套家长身份，多科目存档

业务主键使用稳定的内部账号 ID，手机号作为绑定的登录凭证；本期不提供换绑。页面显示用户名，不编辑昵称和头像。存档按账号、学习档案、科目隔离；首期一个默认学习档案即可，多孩子切换与多家长共享需要另行确认。

三个花园可共享同一来源下的账号服务及 `/api/`。本次沿用并启用了 `https://nmwei.cn/abc-garden/`、`/reading-garden/`、`/math-garden/`，根路径提供个人项目入口；`www` 跳转到主域名。

同源子目录并非安全隔离。采用主域名方案时，未来不受同等信任的实验站应放独立子域名；会话 Cookie 不扩散到整个父域。实际 PWA 的登录共享能力需真机验证，不能仅凭相同域名承诺一次登录所有主屏幕应用。

### D3. 同仓前后端与独立数据库

ABC 仓库已迁入以下结构，运行数据和凭证保留在 Git 忽略目录。

```text
abc-garden/
├── web/          # 原网页、学习模块、素材、PWA
├── server/       # Node 账号与存档 API、数据库迁移
├── scripts/      # 开发、构建、发布工具
├── docs/
└── package.json
```

前端沿用原生 HTML/JS/CSS。移动文件时同步更新构建、测试、素材引用、SW、开发服务和发布白名单，兼容当前域名的本机数据及 PWA 更新。本文模块入口均对应 web/ 下的路径。根目录提供一个命令启动本地前后端，开发环境同源代理 /api/。

Nginx 提供 HTTPS 与静态页面，/api/ 反代到仅本机监听的 Node 服务。网站地址保持 /abc-garden/、/reading-garden/、/math-garden/。后端按科目划分数据，阅读与数学后续共享账号服务，各自保留独立前端仓库与学习逻辑。

首期使用 SQLite，数据库在发布目录外的持久目录，独立权限。数据库迁移需版本化，升级前备份，程序回退与数据库兼容性分别验证。运行密钥放在服务端配置。数据库、密钥及服务器源码不进入静态发布目录。多实例写入或持续高写并发出现时再评估数据库扩展。参考 [SQLite 适用范围](https://www.sqlite.org/whentouse.html)。

数据库职责按以下逻辑实体组织，具体表名在实现时确定。

| 实体 | 职责 |
| --- | --- |
| 家长账号及凭证 | 内部 ID、手机号绑定、用户名、密码哈希、状态 |
| 登录会话与验证状态 | 服务端会话、过期和撤销、验证码请求与核验状态、密码重设验证及限流计数 |
| 学习档案 | 首期默认一份，预留后续多孩子扩展 |
| 科目存档 | 账号及档案归属、科目、格式版本、内容版本、快照、revision、更新时间 |
| 冲突及删除记录 | 保留冲突双方、处理状态，防止旧设备或备份恢复复活已删除数据 |

Node 由服务管理器启动、重启和收集运行日志，提供健康检查。后端版本独立发布，失败恢复旧程序时校验数据库兼容性。garden-hosting 管理 Nginx、服务配置与部署入口。现有本地语音生成服务继续用于开发素材维护，生产账号服务单独实现。

### D4. 首期登录选择与外部依赖

用户已确认当前个人主体无法使用所需微信登录，本期移出微信接入及资格核验。此结论来源为用户提供的审核确认。

首期采用独立的注册表单与两种登录入口。注册需要用户名、密码、确认密码、手机号验证码和家长同意；短信登录只访问已有账号，不自动创建账号。游客可继续本机学习。通过安全会话减少重复收码，敏感操作再次验证。账号使用内部 ID，号码是可更换的凭证。

阿里云 PNVS 短信认证官方支持个人实名认证用户使用预置签名与模板，提供发送和核验 API。用户已确认充值及 PNVS 短信认证开通，每日发送预算为 1 元。服务端按北京时间自然日事务预占预算，按实际配置的计费单价核算，超时保守保留占用，避免重试突破额度。专用 RAM 发送权限与本机忽略配置已完成，真实收码、注册和首次云端保存已通过用户本人操作验证；不记录手机号、验证码或密钥。参见[个人开发者接入指南](https://help.aliyun.com/zh/pnvs/use-cases/sms-verify-for-individual-developers)。

用户已接受仅短信验证可访问旧存档的号码回收风险，并进一步要求两种登录方式共用账号。注册填写用户名（3–24 位、英文区分大小写）、密码及确认密码（8–128 位，允许纯数字）、手机号并验证短信。确认密码仅前端比对，不发送或存储第二份密码。登录支持用户名或手机号加密码，以及手机号加验证码。忘记密码通过短信验证重设，并撤销旧会话。不提供昵称和头像编辑；历史数据库列暂保留兼容，接口不返回这两个字段。默认创建一个学习档案。登录后保留长期有效会话，重设密码需验证短信，成功后撤销旧会话。已实现 180 天不活跃过期、活跃自动续期并设置 365 天绝对上限的服务端可撤销会话，通过 HttpOnly、Secure Cookie 持有。服务端已覆盖长期续期验证，真实浏览器受系统清理网站数据等因素影响，不能保证永久保留登录。清除浏览器数据、退出、撤销、到期或异常安全状态后重新登录。

用户已接受号码回收风险，短信仍可独立登录，不引入额外恢复码验证。本期不提供换绑手机号。忘记密码通过绑定号码验证码重设；旧号码不可用时仍可使用正确用户名和密码登录。既无密码也无法收码时，不能承诺找回。

Apple 登录个人开发者可接入，但网页需要关联启用该能力的主 App ID。官方环境配置文档明确要求已有使用 Apple 登录的 App Store 应用。现有仓库为网页/PWA，尚无满足该要求的应用证据，因此推荐后续有原生应用时再评估。参见[网页配置](https://developer.apple.com/help/account/capabilities/configure-sign-in-with-apple-for-the-web)与[环境要求](https://developer.apple.com/documentation/signinwithapple/configuring-your-environment-for-sign-in-with-apple)。

首期覆盖注册、双登录、短信重设密码、当前设备退出、自动同步、手动存档与恢复。用户明确移除资料编辑、换绑、退出全部设备、注销和个人数据下载，前端与对应 API 一并移除。微信移出本期，Apple 和邮箱登录保留为后续扩展。

### D5. 本地优先，云端保存要有明确确认

- 游客的配置和进度保存本机，清除网站数据会丢失游客记录。登录后仍先保存本机，再同步当前账号的数据库存档，断网继续学习。
- 家长能区分“已存本机”“等待同步”“已存云端/时间”“同步失败”。不能把请求发出等同云端成功。
- 首次登录先读云端。云端为空时，由家长确认将当前游客记录保存到账号。云端已有数据时预览并明确选择，替换前需明确确认，本机原代次保留。新设备空档不得覆盖云端。
- 当前用户数据使用固定本机键。接入账号时，游客、账号、学习档案必须分区；旧游客档案只认领一次，切换账号不能重复认领同一份数据或自动上传前一人的存档。
- 首期采用带格式版本的快照与服务端 `revision` 条件更新；版本比较和写入在数据库事务内完成。重复重试不重复计入学习成果。
- 两端同时修改时保留冲突双方，暂停该档案自动覆盖，家长可选择恢复哪一份；首期不承诺无感自动合并。
- “取消掌握”和“重置”必须被保留，不能用取最大进度、true 优先或简单并集来合并。中途学习队列也不能直接拼接。
- 退出/切账号时隔离本地缓存、内存和待同步任务；旧账号的延迟响应不得写入新账号。退出过程先提示尚未上传的数据并提供处理路径。
- 不支持的格式或损坏数据保留原档并阻止覆盖。恢复多模块失败时不可留下无法辨认的半份档案；被替换的本机代次保留，云端不会自动创建手动存档。
- 清除网站数据后只能恢复最后成功同步的内容；未上传的离线修改无法保证找回。

### D5.1 自动同步与手动存档分离（用户最终确认）

- 每个档案保存一份最新进度，学习变更后自动同步；这份记录不进入手动存档列表。
- “立即同步”改为“存档”：等待进行中的自动同步结束，再将当前本机进度与一份手动快照在同一事务中保存。
- 独立 `archive_checkpoints` 表最多保留最近 3 份手动快照；自动写入任意次数均不会挤掉手动快照。内容未变化且同一 revision 重复点击或网络重试，不重复占用名额。
- 历史列表仅显示手动存档。恢复某份快照只更新最新进度，不自动多建一份手动快照。
- 模式 v3 保留账号、会话和最新进度，移除旧的自动历史表，建立独立手动存档表；升级本机前保存加密备份。旧自动历史不伪装成用户创建的手动存档。

### D6. 云存档上线必须同时具备恢复和访问控制

会话使用 HTTPS 安全 Cookie、服务端鉴权、合理过期与撤销，写接口防跨站请求；密码方案使用成熟密码哈希实现。服务端依据会话确认档案归属，不信任客户端传入的账号 ID，并限制请求大小和频率。

API 和登录回调不进 SW/浏览器共享缓存，响应 `no-store`。ABC 当前不会主动缓存普通 API，但阅读 SW 会缓存作用域内部分成功 GET；三个项目接入时统一验证，不能复制 ABC 的假设。

先完成异机加密备份、保留周期、恢复演练，再把云存档作为可靠恢复能力上线。建议首期每日备份、保留最近 7 日及每周 4 份，目标故障数据损失不超过 24 小时；这是待确认目标，不是现有保证。备份位置、费用和密钥保存方式在实施时落实。

公开云存档前，落实监护人告知/同意、儿童隐私说明、与实际功能一致的说明、保存期限及联系渠道；仅收必要的学习数据，不要求儿童实名/生日/照片。相关要求参照[儿童个人信息网络保护规定](https://www.cac.gov.cn/2019-08/23/c_1124913903.htm)。按实际备案主体和业务核对适用要求，不将实现这些技术措施等同于已满足全部运营义务。本期无自助注销入口；底层备份恢复仍兼容已有删除台账，作为历史恢复保护，不对用户提供删除 API。

### D7. 公开注册的最低运行保障

- 注册及登录验证所选凭证的控制权；验证码/恢复令牌限时、限次、一次性，校验在服务端完成；找回入口不泄露账号是否存在，恢复后撤销旧会话。参考 [OWASP账号恢复指导](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。
- 按 IP、目标账号/手机号/邮箱限制注册、验证码发送、校验失败和恢复请求；异常触发额外验证，避免将单个共享网络的正常家庭永久封禁。
- 若启用外部付费验证服务，发送前预占额度，设置服务端日/月发送上限及预算告警，超时不盲目重发。平台告警不能当作硬性费用上限，具体额度待渠道确定；达到发送上限时说明暂不可验证，已有会话及本机学习继续可用。
- 限制单次存档大小、单账号容量和同步频率；不接受任意大文件或录音上传。日志不记录验证码、密钥和完整儿童档案，联系标识按需要脱敏。
- 保留暂停新注册的运维开关，避免故障扩散；与既有账号登录/恢复接口分开控制。初期用简单配置和受控命令即可，不先建设复杂管理后台。
- 正式开放前执行有限并发、越权和失败恢复验证，并监测接口错误、发送额度、磁盘及备份失败；确认账号服务压力不会阻断静态学习。
